## Modern controls (branch `modern-controls`)

Plan: `docs/superpowers/plans/2026-10-14-jfg-modern-controls.md` (its Findings section holds the reverse-engineered facts). Spec: `docs/superpowers/specs/2026-10-14-jfg-modern-controls-design.md`.

**What it does.** A "Modern" control scheme, on by default; "Original" is the N64 controls, unchanged.

- **Free camera.** The right stick or mouse orbits the game's own follow camera and tilts it up and down. The tilted camera is kept in front of walls and ceilings with the game's own ray cast. After 1.5 s without look input it drifts back behind Juno while she runs. Aim with hip fire is the game's own auto-aim.
- **Aim mode.** Hold Aim (RMB / LT) for the game's R aim mode.
  - The mouse moves the crosshair, and pushing past its box turns the body. The right stick uses the original mapping and rim turning on the N64 range.
  - The left stick / WASD walks and strafes while aiming.
  - With the zoom weapon, the wheel or LB/RB zoom.
- **Code.** `src/jfg/controls/` holds the pure logic (unit tests in `tests/controls/`) and `hooks.cpp` (game hooks, registered in `recomp/jfg.toml.in`). The frontend parts are in `src/game/controls.cpp` and `src/game/input.cpp`.

**Settings** (General tab; saved in `general.json` under `"controls"`): control scheme, camera drift-back (Off, or 0.1–5 s), stick look speed, aim sensitivity, mouse/stick Y inversion, and aim button hold or toggle. The existing Mouse Sensitivity slider scales mouse look and aim; its default is now 50 (old configs with 0 are raised once).

**Default bindings** (Controls tab, "(Modern)" rows; mouse buttons and the wheel bind in the keyboard column):

| Action | Gamepad | Mouse + keyboard |
|---|---|---|
| Move | left stick | WASD |
| Look / aim | right stick | mouse |
| Fire | RT | left button |
| Aim | LT | right button |
| Jump | A | Space |
| Crouch / roll | B | Left Ctrl |
| Previous / next weapon (zoom when aiming the zoom weapon) | LB / RB | wheel down / up, Q / E |
| Quick weapons 1–4 | D-pad | 1–4 |
| Strafe left / right (C-left / C-right; some menus use them) | X / Y | ← / → |
| L (menus) | left stick click | Tab |
| Pause | Start | Enter (Esc opens the port's menu) |

**Development switches:**
- `JFG_DEBUG_CONTROLS=1`: one line per frame for player 1:
  - gate, state, facing, orbit, camera;
  - input: look, mouse and move;
  - free camera: `fc`;
  - aim: offsets, pitch base and mouse mode;
  - speeds while aiming.
- `JFG_CONTROLS_SCHEME_FLIP_AT=<seconds>`: flips Modern/Original once, that long after the first controller read, without saving.
- `JFG_INPUT_SCRIPT` entries take optional look fields: `T+D BUTTONS X Y RX RY MDX MDY` (right stick −1..1, mouse counts per frame). For example, `289+1 R 0 0 0 0 30 0` holds aim and moves the mouse right.
- In the Goldwood script, Juno stands controllable from about 287 s to 296 s, a safe window for scripted tests.

Known tuning points:
- **Mouse look lag.** The game smooths its camera position toward the orbit in about ⅓ s, so mouse look trails slightly.
- **Look-ahead.** The game aims its camera a little ahead of Juno's facing, so after looking sideways she sits off-centre.
- **Wheel zoom.** One wheel notch is a one-frame press, so it zooms only a little.

## Root causes found in this stretch (all fixed, see `git log`)

| Symptom | Cause |
|---|---|
| Crash in `resume_thread` | `osCreateThread` unidentified. |
| "Failed to find function" | The module DMA hook expected code-only loads; the lazy linker loads code+data+imports. |
| Crash on module 56 | Empty module descriptors share ROM addresses; registrations must be dropped when overlapped. |
| Intermittent startup crash | Race in the runtime VI thread (null mode before `osViSetMode`); runtime patch 0001. |
| Black / degenerate 3D | JFG needs the FPU in FR=1 (odd float registers); the runtime starts threads in FR=0. |
| Anti-piracy check failing | The CIC-6105 challenge is the caller's 16-byte buffer, not PIF offset 0x30. |
| Stale module registrations | The game frees modules without the unload hook; registrations now follow the game's module table (entry +0 = current address). |
| Scrambled geometry, flat textures | RT64 masked data addresses to 8 bytes; JFG's 10-byte vertices are unaligned. |
| Garbage save label "1AAAAKU" | Runtime zero-filled new FlashRAM saves; erased flash is 0xFF (runtime patch 0002). |
| Missing name-entry key caps | Absolute matrices in slots 1–3 went through RT64's inverted-MVP path; they're now the projection. |
| Space scenes flat colour, interiors hazy | Billboard sprites weren't offset by their anchor (vertex 0) and became screen-sized quads. |
| No cutscene letterbox, stretched cutscenes | JFG letterboxes via the VI (smaller vertical region, larger Y scale); RT64's VI view/crop rectangles were stubs. |
| "SP CRASHED / DP CRASHED" screen | Rare's hang watchdog (11 retraces per graphics task) tripped on host presentation stalls; thresholds raised. |

## Setting up on a new machine

To just play, `./install.sh path/to/rom.z64` does everything below and installs the game (see `README.md`).

The ROM is not in the repo. Put your dump at `jfg.z64` in the repo root (MD5-checked by `romtool verify`).

```bash
git clone https://github.com/yeehahboogie/jfg-recomp.git && cd jfg-recomp
git submodule update --init --recursive
scripts/apply-lib-patches.sh                      # RT64 + N64ModernRuntime patches (lib-patches/<lib>/)
sudo apt-get install -y clang lld llvm cmake ninja-build make g++ libsdl2-dev libgtk-3-dev libfreetype-dev
#   (without sudo: rebuild .toolchain/ from apt-get download + dpkg -x and `source tools/toolchain.env`)
python3 -m venv tools/romtool/.venv && tools/romtool/.venv/bin/pip install -e 'tools/romtool[test,disasm]'
cmake -S lib/N64Recomp -B build/tools/N64Recomp -G Ninja -DCMAKE_BUILD_TYPE=Release -DCMAKE_C_COMPILER=clang -DCMAKE_CXX_COMPILER=clang++
cmake --build build/tools/N64Recomp
make -C lib/n64sym
scripts/recompile.sh                               # ROM -> ELF -> generated/ (C + RSP)
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=RelWithDebInfo -DCMAKE_C_COMPILER=clang -DCMAKE_CXX_COMPILER=clang++
cmake --build build --target JFGRecompiled
scripts/test-hooks.sh                              # native unit tests
tools/romtool/.venv/bin/pytest -q tools/romtool    # romtool tests
```

The first run of `build/JFGRecompiled` asks for the ROM in the launcher. For development, set `APP_FOLDER_PATH=$PWD/build/appdata` to keep config and saves inside `build/`.

## Player tools (2026-10-16)

- **Frame interpolation (in progress):** no menu row yet (with only the camera interpolated, objects would shake against
  the track's absolute draws); `JFG_INTERPOLATION=1` switches it on for development. The setting is
  `controls.interpolation` in `general.json`, off by default.
  - Spec: `docs/superpowers/specs/2026-10-16-jfg-frame-interpolation-design.md`. Plan 1 (probe, plumbing, cameras):
    `docs/superpowers/plans/2026-10-16-jfg-frame-interpolation.md`, whose Phase 0 findings map every kind of matrix.
  - Done: each frame's matrix identities reach RT64 with the game's frame rate. Every JFG matrix is drawn as-is unless
    identified, so the old heuristic pairing is gone even with the toggle off. World cameras are identified and paired
    by ID, with cut detection.
  - Still steps at 30 fps until plan 2: characters, objects, the sky and other absolute draws, sprites and particles.
  - Not yet seen on a real display: the virtual display doesn't pace presents, so smoothness needs a look on real
    hardware (toggle on, Framerate Display or Manual above 30).

- **Stats overlay:** F3, or General → Stats Overlay (saved).
  - **Shows:** game FPS (player 1 controller reads), render FPS and frame time (RT64 presents, counted by `RT64::presentedFrameCount` in the RT64 patch), level number and name, player 1's position, and queued audio.
  - **How it's built:** `src/ui/ui_stats_overlay.cpp` and `assets/stats_overlay.rml`, in a context that captures no input.
- **Cheats tab** (`assets/config_menu/cheats.rml`, model in `src/ui/ui_config.cpp`): Invulnerability, All Weapons and All Levels (the game's flags), Infinite Ammo, Big Heads, Refill Health, Level Select (Warp) and Skip Ahead (take one of the current level's exits).
  - **Big Heads:** `src/jfg/big_head.cpp` hooks the end of `modGenAnimMatrices` (0x8003D21C) and doubles the head joint's matrix (and the joints below it) about the head's pivot, for every model with 8 to 64 joints. The head is found from the model's skeleton (`src/jfg/skeleton.cpp`, tested by `tests/skeleton_test.cpp` with real skeletons): from the joint highest in the bind pose, the first joint up its chain on the body's centre line, so hair buns (Vela), ears (Lupus, Magnus) and antennae (ants) lead back to the head; a "head" carrying more than half the model (the name-entry keyboard) is left alone. `JFG_DEBUG_BIGHEAD=1` logs each model's name and the joint chosen.
  - **How they reach the game:** the game side lives in `src/jfg/level_hooks.cpp` (`player_tools_tick`). Requests go through `jfg::Mailbox` and run at player 1's next gameplay frame.
  - **Memory used:**
    - the game's cheat flags `allLevelCheat`, `invulnerabilityCheat`, `allweaponsCheat` (`0x800A5068`, `0x800A5070`, `0x800A5078`) are **bytes** (the game reads them with `lbu`). Invulnerability is the game's own: when health runs out, the character's control code refills it (`0x2200` for 6 segments) instead of dying. All Weapons makes it set owned weapons to `0x7FFF`;
    - the stats struct from `0x80047C1C(pd[0], pd[1])`: owned weapons at `+0x0A`, ammo at `+0x14 + 2w`, ammo cap at `+0x34 + 2w`, health segments at `+0x02`;
    - health: the halfword at `*(player + 0x4C) + 6`, full = `((segments × 5) + 4) << 8`.
- **Level names** are read from the ROM: asset table `*0x800FE070`, assets 0x1E (offsets) and 0x1F (32-byte names) at ROM `0xB1880 + offset`.
  - Calling the game's `levelGetName` during play allocated and freed memory and broke the next level load (division by zero in `trackInit`).

To Goldwood gameplay (Magnus greets Juno at ~310 s), append: `; 230+0.3 A; 245+0.3 A; 260+0.3 A; 275+0.3 Z; 296+4 - 0 1; 302+2 - 1 0`. |
| `JFG_DEBUG_MODULES=1` | Module loads, DMAs, lazy links and the CIC result. |
| `JFG_DEBUG_REGISTRY=1` | Checks registered module code against ROM. |
| `JFG_DEBUG_GBI=<seconds>` | Logs `JFG_DEBUG_GBI_LINES` (default 400) display-list commands after a delay. |
| `JFG_DEBUG_XFORM=1` | Compares RT64's vertex transforms with a GLideN64-model shadow. |
| `JFG_DEBUG_TRIDUMP=<file>` | With `XFORM` and `GBI`: dumps reference clip-space triangles. |
| `JFG_DEBUG_RDRAM=<file>` | With `GBI`: dumps RDRAM (8 MB, console byte order) at a display-list start. |
| `JFG_DEBUG_TEXDUMP=<dir>` | Texture load sources. |
| `JFG_NO_VSYNC=1` | Present without vsync. With vsync, a window the compositor isn't showing (screen blanked, minimised) is paced at ~1 Hz by XWayland. The test scripts set it by default. |
| `JFG_INPUT_CLOCK=frames:<rate>` | Times `JFG_INPUT_SCRIPT` by controller reads (one per game frame; 30 per second normally) instead of the wall clock, so scripted presses still land when the machine is busy. The survey scripts use `frames:30`. `JFG_DEBUG_INPUT_CLOCK=1` logs reads against wall time. |
| `JFG_DEBUG_FBTEX=1` | Logs the first 40 draws that sample a framebuffer as a texture: formats, size, reinterpretation (RT64 patch). |
| `JFG_FAKE_PLAYERS=<n>` | Reports players 1..n connected without gamepads, for testing multiplayer. |
| `JFG_INPUT_SCRIPT_P2="…"` | Scripts player 2 like `JFG_INPUT_SCRIPT`, on the same clock. |
| `JFG_CHEATS=invuln,weapons,levels,ammo,bighead` | Starts with those cheats on (the Cheats tab's switches): invulnerability, all weapons, all levels, infinite ammo, big heads. |
| `JFG_INTERPOLATION=1` | Frame interpolation on regardless of the General-tab toggle (scripted runs). |
| `JFG_DEBUG_INTERP=1` | Frame interpolation: once per graphics task, cameras and models tagged or unknown (drawn as-is); camera cuts; once a second, RT64's decision (game rate, target rate, whether in-between frames are generated); every 60th camera pairing (IDs, mapped). |
| `JFG_DEBUG_MTXSRC=<frame>` | Logs which code converted each matrix of that frame and every matrix load of the graphics tasks around it; `tools/diag/mtx-provenance.py` joins them. |
| `JFG_DUMP_OBJECTS=<file>` | Every 15 frames, appends every object (0x80 bytes) and its data block (0x100 bytes, object +0x68) to `<file>`, for finding fields such as a boss's health by diffing. Format in `src/jfg/level_hooks.cpp`. |
| `JFG_AUDIO_DUMP=<file>` | Writes every chunk of sound the game produces (signed 16-bit stereo, 22020 Hz, before resampling) to `<file>`, and `<file>.index` (chunk number, first frame, frames). `tools/diag/audio-scan.py` finds bursts of static in it or in a WAV. |
| `JFG_DEBUG_AUDIO_QUEUE=<file>` | Logs every chunk the frontend queues to SDL: input samples, bytes already queued, skip ratio, bytes queued, peak and non-finite values, and the SDL audio driver. |
| `JFG_AUDIO_DISK=<file>` | `scripts/screenshots.sh` uses SDL's disk driver: SDL's own output as raw 32-bit float stereo at 48 kHz, bypassing the sound server. |
| `JFG_AUDIO_SINK=<sink>` | `scripts/screenshots.sh` sends the sound to that PulseAudio sink instead of the silent dummy driver (set by `tools/diag/capture-audio.sh`). |
| `JFG_BINARY=<path>` | `scripts/screenshots.sh` runs that build instead of `build/JFGRecompiled` (A/B comparisons against a saved copy). |
| `JFG_ALIST_LOG=<file>` | Per audio task: its number and how many of each audio command it has. |
| `JFG_ALIST_DUMP=<task>` | Writes RDRAM before and after that audio task and the next two, plus the OSTask, to `build/diag/audio/task<N>.{before,after,task}`, for replaying a task outside the game. |
| `JFG_DEBUG_PILLARBOX=1` | Logs every full-screen 2D layer that pillarboxes a frame: triangles, bounding box, coverage, texture span and colour (RT64 patch). |
| `JFG_DEBUG_TASKTIME=1` | Logs graphics tasks / presents slower than 50 ms (runtime patch 0003). |

Scripts:

- `scripts/smoke.sh [seconds]`: boot health check.
- `scripts/screenshots.sh OUT_DIR [seconds…]`: autostart and screenshot the window (fractions allowed); honours `JFG_INPUT_SCRIPT`.
- `tools/diag/`: display-list walker, offline rasteriser, GDB-stub memory dumper, virtual gamepad (see its README).
- `tools/diag/capture-audio.sh PROCESS OUT.wav COMMAND…`: records a run's real sound output (`JFGRecompiled` through `scripts/screenshots.sh`, or `ares`) to a WAV through a temporary null sink, so nothing plays on the desktop. `tools/diag/ares-audio.sh OUT.wav OUT "SCRIPT" SECONDS…` wraps it for ares.
- `tools/diag/ares-shots.sh OUT "SCRIPT" SECONDS…`: ares driven by the virtual pad, screenshotted at the same moments. It moves ares's `jfg.flash` to `jfg.flash.bak` first. ## The ares reference

ares is installed as a user flatpak (`dev.ares.ares`). On this machine its settings (`~/.var/app/dev.ares.ares/data/ares/settings.bml`) are as follows:

- `VirtualPad1` is bound to the `tools/diag/vpad.py` virtual pad (`python3 tools/diag/vpad.py guid` prints the binding strings).
- The GDB debug server is off. Turn on `DebugServer/Enabled` (port 9123) only while dumping memory; with `UseIPv4: true` it listens on all interfaces.

ares writes `jfg.flash` next to the ROM; `*.flash` is now git-ignored.
